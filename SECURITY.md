# Security Policy

## Reporting a Vulnerability

Do not disclose a suspected vulnerability in a public issue or discussion.
Submit it through GitHub's
[private vulnerability reporting form](https://github.com/7thsense/fjord/security/advisories/new).
If the form is unavailable, open a
[security contact request](https://github.com/7thsense/fjord/issues/new?template=documentation.yml&title=Security%20contact%20request)
using the documentation issue form. State only that you need a private contact
channel; do not include vulnerability details, affected components, reproduction
steps, or other sensitive information in the public issue.

Include the affected version or commit, deployment assumptions, reproduction
steps, impact, and any suggested mitigation. Do not include real credentials or
data belonging to other people.

Maintainers will confirm receipt, assess the report, and coordinate disclosure
and remediation as appropriate. Response and release timelines depend on the
report's scope and severity; the project does not currently promise a fixed
service-level agreement.

## Supported Versions

Fjord is early-stage software and has not declared a production-supported
release line. Security reports are assessed against the latest release and the
current `main` branch. Older releases may not receive fixes.
